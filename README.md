# Avito NLP Candidate Generation

## Что изменилось

### Обучаемый прогноз микрокатегории

Большинство benchmark-запросов не встречаются в train в той же локации.
Поэтому V5 дополняет поиск ближайших train-запросов классификатором
`MultinomialNB` из scikit-learn. Он учится на текстах `search_query +
search_infm_params_text`, представленных символьным TF-IDF, и предсказывает
`item_microcat_id` выбранного объявления. Повторные клики по одной паре
«запрос, фильтр, объявление» удаляются перед обучением.

Для новой формулировки прогноз классификатора смешивается с прежним прогнозом
с весом 0.5; для уже известной — с весом 0.2, чтобы точная история оставалась
главным источником. В geo-квоте рассматриваются до восьми микрокатегорий.
Это мягкий прогноз: объявления других подкатегорий не отбрасываются.

На отдельной проверке 3 200 полностью новых сочетаний «запрос + фильтр»
точность первой микрокатегории выросла с 0.721 до 0.749. Это диагностическая
метрика классификатора, не Recall@50.

### Нулевые совпадения больше не участвуют в RRF

Раньше каждый лексический канал отдавал top-150 даже тогда, когда текст запроса
не встретился ни в одном документе данного пула. Из-за одинаковых нулевых
оценок туда попадали произвольные объявления; при повторном поиске внутри
географического и filter-пула этот шум усиливался.

Теперь канал передаёт в RRF только объявления с положительной оценкой.
Это применяется и к глобальному поиску, и к поиску внутри geo/filter-пулов.
Dense-каналы и остальные квоты остаются доступными, поэтому отсутствие
лексического совпадения не делает ответ пустым.

## Локальная проверка Recall@50

Из train выбраны 300 запросов, у которых есть выбранные объявления в
`benchmark_items.parquet`. **Все строки этих запросов удалены из обучения**,
включая статистику кликов и query profiles. Для каждого запроса оценивается
доля его выбранных объявлений из доступного корпуса, попавших в top-50.
Все варианты используют одно разбиение и один обученный индекс.

| Вариант | Recall@50 |
|---|---:|
| V4 | 0.8247 |
| Только отсечение нулевых оценок | 0.8381 |
| Только классификатор микрокатегории | 0.8358 |
| V5: оба изменения | **0.8458** |

У V5 относительно V4 улучшились 8 запросов, ухудшился 1, остальные не
изменились. Локальная выборка проще скрытого бенчмарка: её 0.8458 нельзя
сравнивать напрямую с конкурсными 0.735160. Конкурсный результат V5 нужно
измерить отдельной отправкой.

Проверку можно повторить скриптом `validate.py`, лежащим рядом с `model.py`.
Он читает данные из текущего рабочего каталога и использует локальный кеш
MiniLM в `artifacts/`:

```bash
cd /path/to/AvitoNlp
.venv/bin/python /path/to/avito_v5/validate.py
```

## Подключение

Для запуска достаточно поместить приложенный `model.py` вместо
`app/model/model.py`. Интерфейс проекта не меняется:

```python
model = CandidateModel()
model.fit(train, items)
predictions = model.predict(queries)
```

Новых зависимостей нет: `MultinomialNB` и `TfidfVectorizer` уже входят в
scikit-learn из текущего `requirements.txt`. Эмбеддинги объявлений MiniLM
используют прежний кеш; классификатор обучается заново при каждом `fit()`.

Основной запуск проекта:

```bash
source .venv/bin/activate
python main.py
```

### Запуск через Docker

После размещения V5 в `app/model/model.py` выполните команды из корня проекта.
Каталог `data/` должен содержать три исходных parquet-файла.

```bash
mkdir -p output artifacts
docker build -t avito-nlp:v5 .
docker run --rm \
  -v "$(pwd)/data:/app/data:ro" \
  -v "$(pwd)/output:/app/output" \
  -v "$(pwd)/artifacts:/app/artifacts" \
  avito-nlp:v5
```

Результат появится в `output/answer.csv`. Каталог `artifacts/` хранит MiniLM
и эмбеддинги объявлений между запусками. При первом запуске без локального
кеша MiniLM загрузится с Hugging Face; для полностью офлайн-запуска заранее
поместите модель в `artifacts/huggingface/` и сохраните этот каталог при
монтировании. Текущий Dockerfile уже устанавливает все зависимости V5.

Файл `output/answer.csv` формирует существующий `main.py`. V5 сохраняет
ограничение на 50 уникальных `item_id` из корпуса и категорию услуг `114`.
